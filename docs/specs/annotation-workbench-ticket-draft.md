## 发布时随每票携带的约定

- 每票引用父规格，携带自己的交付行为、验收条件及直接阻塞任务；发布时使用 ready-for-agent 标签并建立原生父子及阻塞关系。
- 中文界面、任务及错误；使用通用题型名称和自制无品牌素材，不发布私有路径、图片或密钥。
- 产品是 Electron + React + TypeScript。基础组件采用 shadcn/ui，聊天按需采用 beUI，图标统一 Lucide。正式布局采用已选原型 A：全局菜单、项目与会话列表、主聊天、右侧停靠多标签面板。
- 原型只作视觉与交互参考，正式实现从主分支的生产基线起步；不整体合并原型代码。原型分支 prototype/agent-workbench，选型记录 ace7748，目前仅在本机。B/C、设计切换条及模拟数据不进入正式产品。
- 当前只有原型和需求文档，没有需要先做的大范围重构。项目配置、术语与正式规格应纳入生产基线，保留用户已有改动。
- Agent 通过对话和工具自主推进，Prompt 引导样本观察、测试、验证和扩大处理范围；不设置试跑或批量启动按钮及审批状态。数据校验、版本检查与人工复核约束仍然执行。
- 每票覆盖自身用户行为所需的 UI、应用接口、保存和验证，不能仅交付空界面或孤立底层模块。沿用用户已确认的工作台公开流程及标注数据/导出契约两类测试边界。
- 外部模型可用可控服务替身；生产应用的处理、保存、渲染和校验真实执行。真实服务验收单独记录，凭据缺失时报告阻塞，不能以替身冒充。
- 自有业务代码遵守 ESLint：圈复杂度 10、函数有效行数 60、嵌套深度 3、参数 4。纯展示组件可在明确范围将长度放宽到 100，复杂度不放宽；第三方组件独立范围管理，例外记录理由，警告也阻断。
- 从 T01 建立严格类型检查、行为测试与 CI。已有核心逻辑按行/语句/函数 90%、分支 85%检查，后续模块加入范围；没有业务逻辑时不以空统计宣称达标。
- T03 的坐标与协议、T07/T11 的状态规则、T12 的导出过滤逐步接入变异测试，初始有效变异得分门槛 80%。中文“假如／当／那么”表达关键验收场景，不强制为语法额外搭框架。

## T01：启动桌面工作台并管理项目与会话

**父规格：** #1。

**阻塞任务：** 无，可立即开始。

**交付行为：** 用户打开实际 Electron 应用，创建项目和会话、在左侧切换，关闭应用后仍能恢复这些记录。界面采用 A 的固定骨架，此票尚不模拟真实 Agent 回复。

**验收条件：**

- [ ] 正式应用可启动和关闭；全局菜单、项目/会话列表、主聊天区域按 A 的结构呈现，包含设置入口。
- [ ] 项目、会话有稳定标识；用户可创建和切换，重新启动后记录仍在，关闭会话不删除项目数据。
- [ ] 主进程管理本机窗口与生命周期，渲染层通过受限 preload 调用应用能力；上下文隔离、Node 集成关闭和 IPC 输入输出校验落地。
- [ ] 实际 Electron 冒烟测试覆盖创建、切换与重启，而非只测普通网页。
- [ ] 正式依赖、类型检查、ESLint、行为测试和 CI 可运行，加入一段故意超限的临时示例可验证质量检查确实失败，验证后移除示例。
- [ ] 不把三套原型或模拟标注带进生产入口，保留原型分支可回溯。

## T02：导入项目图片并从会话查看产物

**父规格：** #1。

**阻塞任务：** T01。

**交付行为：** 用户向项目导入本机图片文件夹，在会话中查看批次引用并打开右侧图片标签；切换会话和重启后恢复各自布局。

**验收条件：**

- [ ] 本机文件夹选择或路径输入建立批次，记录图片标识与尺寸；原图不变，无效路径、不可读图片有中文反馈。
- [ ] 项目持有批次，单会话可引用多个批次，当前操作显示具体目标，项目之间不串用数据。
- [ ] 消息中的图片/批次引用打开右侧标签，同一类型与对象重复打开聚焦已有标签；引用身份独立于当前选中批次。
- [ ] 面板支持调宽、关闭标签、收起及全屏；恢复时保留每个会话的打开对象、活动标签、宽度和展开状态。
- [ ] 关闭标签不删除数据；不存在或无法加载的对象显示可理解的错误，不打开另一个对象代替。
- [ ] 桌面公开流程验证导入、对象去重、项目/会话切换及重启恢复。供未来 Agent 使用的导入/打开能力通过同一应用服务提供。

## T03：按声明式方案完成人工选格标注

**父规格：** #1。

**阻塞任务：** T02。

**交付行为：** 用户用已安装的示例方案查看原图、题目和六个候选区域，修改并确认选格结果。示例是可用方案，不伪装成 Agent 已自动生成。

**验收条件：**

- [ ] 方案契约包含版本、标注字段、界面描述、确认规则、处理定义与导出能力；此票可采用确定性的示例处理器。
- [ ] 图片、文本及选项组件由描述驱动，支持单选/多选；通过同一渲染入口组合不同方案，不写题型专属页面。
- [ ] 题目、稳定选项 ID、原图尺寸、归一化区域及当前选择能保存，修改保留为草稿，人工确认单独记录。
- [ ] 未知协议版本或组件、无效绑定、非法坐标及不满足字段约束的提交被拒绝；未经人工确认不成为已复核结果。
- [ ] 切换标签、收起及全屏不丢草稿，模型建议/初步值与人工值区分保存。
- [ ] 公开标注契约用独立已知值验证坐标和校验，桌面操作验证编辑与确认；为已有关键逻辑加入覆盖率及变异测试。

## T04：配置模型并与内置 Agent 看图对话

**父规格：** #1。

**阻塞任务：** T02。

**交付行为：** 用户分别配置 Agent 和标注 VLM，在项目会话中请求查看已导入样本，内置 Agent 实际调用工具获取图片并回复。

**验收条件：**

- [ ] 设置界面分别配置 Agent/VLM 接口、模型与本机密钥，可使用相同或不同服务；不在日志展示、方案或版本库中泄露密钥。
- [ ] 所选 Agent 运行时支持图片和工具；接入前核实正式 SDK。Agent 在独立工作进程运行，不阻塞 Electron 主线程。
- [ ] 对话、工具活动与错误进入对应会话，切换/恢复后仍保持归属；后台事件不能落到另一个前台会话。
- [ ] Agent 经应用工具读取当前项目样本，消息引用可打开 T02 的面板；没有任务时不伪造执行记录。
- [ ] 接入专用 Prompt：通过聊天理解目标、自行观察样本和利用工具推进；不要求固定阶段审批。
- [ ] 模型替身验证消息、图片和工具边界；小规模真实服务验收实际看图，记录结果或缺失凭据的阻塞。

## T05：Agent 写代码、运行测试并提交可查看方案

**父规格：** #1。

**阻塞任务：** T03、T04。

**交付行为：** 用户描述目标后，Agent 在工作区编写处理代码、执行样本测试并读取结果，生成方案与裁切产物，通过聊天引用交给用户查看。

**验收条件：**

- [ ] Agent 可实际编写与运行代码、执行测试、读取错误和派生产物，任务在独立进程执行，保留原图。
- [ ] 运行进度、完成或失败真实呈现；不把尚未完成或失败的运行声明为成功。
- [ ] Agent 生成的方案通过 T03 同一协议校验后进入同一渲染入口；无效描述或缺少组件能力有明确反馈。
- [ ] 示例代码产生题目与候选区域；裁切和缩放映射可回到原图，用户能查看原图及裁切结果。
- [ ] 用户在聊天中指出问题后，Agent 能调整代码并再次测试；面板查看不触发处理流程。
- [ ] 可控 Agent 工具轨迹驱动真实代码运行、产物提交及校验；真实小样本验收验证看图到代码测试的链路。

## T06：Agent 通过 VLM 生成初步标注并复用方案

**父规格：** #1。

**阻塞任务：** T05。

**交付行为：** Agent 按方案调用标注 VLM 生成可复核结果，保存方案，在用户后续导入的同类批次中复用。

**验收条件：**

- [ ] 通过已配置的 OpenAI 兼容服务识别图片，将响应转成题目、候选区域和选中项等契约数据；OCR 可选，不固定识别链路。
- [ ] Prompt 默认引导少量样本验证后扩大范围，Agent 自行依据结果继续或调整，无试跑审批状态。
- [ ] 网络错误、无效响应、不符合方案的图片及错误坐标单独报告，成功结果为初步标注而非已复核。
- [ ] 方案保存代码、描述及版本，并能由 Agent 在新批次选择复用，不要求重新生成。
- [ ] 用户从聊天引用查看具体结果、原图和方案版本，后台更新不抢当前标签。
- [ ] 可控服务验证解析及失败路径；真实 VLM 小样本走同一校验和面板呈现。

## T07：Agent 批量处理与失败重试

**父规格：** #1。

**阻塞任务：** T06。

**交付行为：** 用户通过对话表达批量目标，Agent 调用工具处理明确范围的图片，报告进度和失败，按需要重试。

**验收条件：**

- [ ] 工具可直接执行批量处理，无页面启动按钮或样本确认审批；仍校验项目、批次、版本和处理范围。
- [ ] 批次区分未处理、处理中、失败和待复核；单张失败不丢失其他成功结果。
- [ ] 初步标注不能由 Agent 自动转为人工确认，无论模型自述置信度多高。
- [ ] 默认只重试失败项；重复调用不会建立重叠执行或重复覆盖成功记录。
- [ ] 用户在聊天中补充约束后，后续操作使用明确目标；任务活动与结果属于发起会话及批次。
- [ ] 公共流程测试部分失败、重试、重复调用和无按钮推进，状态规则加入变异测试。

## T08：以同一组件协议编辑点、矩形框和有序点

**父规格：** #1。

**阻塞任务：** T03。

**交付行为：** 用户打开其他结构化方案，在同一工作面板中编辑点、框和有序点，保存并恢复位置。

**验收条件：**

- [ ] 新增三类标注组件，共用图片、文本、字段绑定和确认操作；不同组合无需独立题型页面。
- [ ] 可创建、修改和删除标注，有序点保留顺序，关闭并打开仍可恢复。
- [ ] 图片缩放与裁切展示不改变最终原图归一化位置，覆盖非正方形图片、边缘坐标和裁切映射。
- [ ] 非有限值、无效框及越界坐标被拒绝；标注矩形与预处理裁切规则相互区分。
- [ ] 不提供专用旋转或滑块工具；没有转换规则的类型不声明可导出 YOLO 检测框。
- [ ] 通过公开契约及真实组件交互测试保存和位置；新组件进入共享注册表，Agent 不使用另一套能力清单。

## T09：连续复核、无法判断与向 Agent 反馈问题

**父规格：** #1。

**阻塞任务：** T07。

**交付行为：** 用户连续检查批量结果，修改题目和选择、确认并下一张；遇到无法判断或裁切错误，可标记并带样本上下文反馈给 Agent。

**验收条件：**

- [ ] 呈现原图、裁切位置、题目、候选图片、模型建议与当前答案；复核明确显示批次和版本。
- [ ] 支持上一张、确认并下一张及快捷键，文本输入时不误切图或误确认。
- [ ] 必填字段与选项约束在确认前校验；编辑已确认结果后重新标为待确认，保留历史确认记录。
- [ ] 无法判断、处理失败和需要修正方案可区分；问题反馈在聊天中关联具体图片及方案。
- [ ] 保留复核草稿；跨会话编辑提交前校验版本，旧页面不能静默覆盖较新的结果。
- [ ] 桌面操作测试导航、焦点、异常标记、草稿及冲突；不增加逐张手工修改预处理裁切规则的功能。

## T10：处理中断后恢复任务与复核进度

**父规格：** #1。

**阻塞任务：** T09。

**交付行为：** 用户在处理中关闭或异常退出工作台，重新打开后恢复结果，通过对话继续未完成任务，人工草稿与确认记录仍然可用。

**验收条件：**

- [ ] 项目、会话、批次、方案、成功结果、复核草稿和人工状态在重启后可恢复。
- [ ] 中断的处理中任务不会被误报成功或永久卡住，Agent 可读取恢复信息并继续明确范围。
- [ ] 区分失败重试与继续未完成项，已成功或已人工确认项不被默认重跑。
- [ ] 持久化保持一致性，不出现已确认状态却缺少数据等半写入记录。
- [ ] 实际终止和重启应用及工作进程，覆盖处理和人工保存附近的中断；不以页面刷新替代。

## T11：方案版本、选择性重跑与历史复核

**父规格：** #1。

**阻塞任务：** T10。

**交付行为：** 用户指出问题后，Agent 生成新方案版本并按明确范围重跑。用户可以查看旧记录，新结果必须重新人工确认。

**验收条件：**

- [ ] 方案修改创建新版本，旧方案及结果可追溯；Prompt 指导验证变更，不建立新的试跑审批门槛。
- [ ] Agent 依据对话目标确定并记录重跑范围，范围外图片保持原状态。
- [ ] 被纳入重跑的已确认图片失去当前导出资格；旧确认保留为历史，新结果不能自动继承。
- [ ] 重跑失败、中断及恢复时不让历史确认冒充当前结果；重新人工确认后才恢复资格。
- [ ] 历史消息打开对应旧版本只读结果，当前可编辑结果区分显示；布局导航不改变业务版本。
- [ ] 公开流程测试多版本、选择范围、失败恢复及重新确认，对资格转换规则运行变异测试。

## T12：导出一致的 JSON/YOLO 数据包并完成贯通验收

**父规格：** #1。

**阻塞任务：** T08、T11。

**交付行为：** 用户表达导出目标后，Agent 调用导出能力生成包含原图副本的数据包，面板呈现结果；以真实小样本验收完整桌面流程。

**验收条件：**

- [ ] 导出固定当前已人工确认的结果集合；未处理、处理中、失败、无法判断、需要修正方案及重跑后待复核均排除。
- [ ] JSON 保留原图标识与尺寸、题目、完整字段、方案版本和确认结果；点、框、有序点的语义不丢失。
- [ ] 六宫格选格可导出 click 类别 YOLO 检测框，位置为完整选中格子的归一化中心点和宽高；附类别说明。
- [ ] 只支持方案明确声明且有转换规则的格式，其他数据不强行转为检测框。
- [ ] 同次导出图片、JSON 和标签集合一致，不因并发复核变更而混用版本；图片命名无覆盖，包内引用可搬移。
- [ ] 密钥和本机私有配置不进入数据包；第一版不自动划分训练集和验证集。
- [ ] 用独立固定预期值验证坐标、过滤及包内一致性，对导出过滤运行变异测试。
- [ ] 小规模真实验收涵盖 Electron、内置 Agent 看图、代码运行、模型调用、声明式面板、人工复核及导出。完成质量检查和最终 QA；未具备真实服务条件时明确列出未完成验收。
