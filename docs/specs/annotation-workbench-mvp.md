# MVP 需求规格：Agent 驱动的通用验证码标注与人工复核工作台

状态：需求、测试边界和原型 A 选型已确认；本规格用于更新 [GitHub Issue #1](https://github.com/moxi-2534/Captcha-Labeling/issues/1)，后续拆票以更新后的该任务为准。

## 问题陈述

不同题型的验证码需要不同的图片预处理、识别规则、标注字段和人工交互。逐类手工编写独立工具会重复实现导入、进度管理、复核、保存与导出；让 Agent 自由生成完整页面又难以维持操作和风格一致。

用户需要在本机导入已有图片，与内置 Agent 对话，由 Agent 查看样本、编写并测试处理代码，形成可复用的标注方案。模型结果必须经过人工逐张复核，最终形成可独立使用的数据包。

## 解决方案

提供基于 Electron 的本机单人桌面工作台，使用 React 和 TypeScript 构建界面。工作台统一管理导入批次、模型配置、Agent 对话、代码运行、试跑、批量处理、人工复核、方案版本和导出。

内置 Agent 生成处理代码和结构化复核界面描述。工作台校验描述，并用已有组件渲染题型所需的界面。Agent 组合已有能力，缺少组件时明确报告，扩展组件由后续开发完成。

采用类似声明式生成界面的思路，定义适合标注场景的小型协议，不要求兼容某个现成 UI 协议。六宫格选图作为首个端到端验收案例，产品流程和数据模型保持通用。

## 实现决策

### 产品边界与内置 Agent

- 单人、本机 Electron 桌面应用；内置专用 Agent，第一版不接入外部 Agent。
- React + TypeScript 构建渲染层，shadcn/ui 提供基础组件，beUI 的聊天组件按需复用；图标统一使用 lucide-react。
- 渲染层负责展示与交互，通过 preload 暴露的窄接口调用应用能力；主进程管理窗口、本机文件选择与生命周期。启用上下文隔离，渲染层关闭 Node 集成，IPC 参数及返回值按契约校验。
- Agent 运行时、处理脚本和长任务放入独立工作进程，持久化状态与事件回传界面；不在 React 或 Electron 主线程直接运行耗时处理。
- UI 组件与 Agent 运行时解耦，beUI 只承担呈现，不据此引入另一套模型编排框架。
- 固定工作台负责项目、会话、批次、阶段、进度和复核操作，Agent 描述只控制标注区域的组件组合。用户已通过原型选定 A「安静分栏」：全局功能栏、项目与会话列表、主聊天区、右侧停靠式多标签面板；面板支持调宽、收起与全屏。
- Agent 可以基于 Pi 实现；最终运行时接入方式在实现时依据其正式 SDK 能力确定，不预设未经核实的接口。
- 提供实际代码执行环境，支持查看样本、编写处理脚本、执行测试、读取产物与错误并迭代。执行过程可观察，代码和派生产物位于工作区，原始图片保持不变。
- Agent 处理代码负责裁切、识别调用和结果转换；复核界面描述负责展示、字段绑定与允许的操作。
- Agent 通过工具自主执行样本检查、代码测试、识别和批量处理。先小样本验证再扩大处理范围写入 Agent Prompt，作为默认工作方法；不设置试跑确认按钮、批量启动按钮或服务端对应审批状态。用户通过对话补充目标、约束和纠正方向。
- 面板用于人工查看产物与复核数据，不承担 Agent 流程编排。人工确认标注仍是独立数据质量条件，Agent 的运行成功不能代替人工确认。
- Agent 模型需支持图片理解和工具调用；标注 VLM 使用可配置的 OpenAI 兼容服务。两者分别配置接口、模型和密钥，可以指向同一服务。
- OCR 是处理方案可选择的步骤，也可以将题目一并交给 VLM；不强制所有方案使用同一种识别链路。

### 工作台布局与项目上下文

- 主工作区以 Agent 会话为中心，聊天输入与消息流是主要入口。
- 最左侧提供紧凑的全局功能图标栏，包含项目切换和设置入口；旁边提供项目内会话列表。导航和聊天组件统一采用既定组件体系。
- 项目是长期工作空间，拥有会话、导入批次和可复用标注方案。关闭会话不会删除批次或方案。
- 一个会话允许处理多个批次。当前操作明确显示目标批次；历史消息中的产物入口绑定具体批次、方案版本和结果，不能随当前批次变化而指向其他对象。
- 右侧工作面板承载图片、试跑结果及 Agent 描述驱动的复核界面，与聊天共享所打开对象的上下文。
- 用户已选定原型 A「安静分栏」。右侧采用会话级停靠工作面板、按对象寻址的标签页、重复打开聚焦已有标签，以及折叠和全屏切换。

#### 右侧工作面板交互约定

- 新会话默认优先展示聊天；用户打开消息中的图片、方案或结果引用时，在右侧显示对应内容。查看入口只负责导航，不执行试跑、批量处理或重跑。后台进度更新不主动抢走用户当前标签。
- 标签身份由视图类型与项目、批次、方案版本、结果标识共同确定；同一对象重复打开聚焦已有标签，不重复创建。不能只用标题或当前批次作为身份。
- 第一版按内容提供图片、方案、处理结果、人工复核及导出产物视图；不组织为必须依次点击的阶段页面。各视图通过统一注册入口渲染，Agent 的声明式 UI 位于相应业务视图内部。
- 顶部标签条承担切换和关闭，尾部提供全屏与收起；收起后从聊天顶栏恢复。面板宽度可调整，全屏退出后恢复原布局。
- 每段会话分别保存面板开关、宽度、已打开对象及活动标签；切换会话后恢复对应布局。持久化对象引用，不将临时组件实例作为恢复依据。
- 切换标签、收起面板和进入全屏不会丢失复核草稿。关闭标签不删除数据或取消后台处理；草稿保留也不等于人工确认。
- 历史结果只读查看与当前结果编辑明确区分；操作提交前校验结果版本，其他会话已更新的对象不能被旧界面静默覆盖。
- MVP 采用单个右侧停靠区域内的多标签，不引入任意分栏、拖出浮窗、通用浏览器或完整插件布局框架。原型 B/C 和设计切换条仅保留在原型分支，正式应用不包含它们。选定布局不代表原型的模拟处理、内存保存或简化实现可直接作为正式功能。
- 参考依据：[右侧栏契约](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/sidebar-right.zh.md) 与 [侧栏容器源码](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-sidebar-right/src/client/shell/SidebarRight.tsx)。此处参考其交互与对象定位原则，未导入其代码或插件体系。
- 切换项目时，其会话列表及当前工作对象保持项目隔离，不把上一项目的批次当作新项目的操作目标。

### 通用标注方案与界面协议

- 标注方案包括处理规则、标注字段、复核界面描述、确认条件、支持的导出方式及版本。
- 描述协议需要明确版本、组件类型、数据绑定与允许操作，并在执行或展示前校验。
- 第一批基础组件包括图片、文本、选项、点、矩形框和有序点；固定工具栏统一提供复核状态、保存、切图和常用快捷键。
- Agent 组合受支持组件；未知组件、无效绑定或无法满足的交互应明确报错，不能默默忽略。
- 不允许通过界面描述注入任意前端代码。现场编写并加载自定义组件不属于 MVP。
- 六宫格是首个完整验收案例；切换方案和组件组合不应要求新增一套独立复核页面。

### 导入、处理与方案版本

- 一个导入批次使用同一套方案；用户选择已有方案或由 Agent 创建。第一版不自动识别混合题型并分流。
- 每张图片有稳定标识，处理结果记录对应方案版本。试跑产物与批量处理结果可追溯。
- 区分未处理、处理中、处理失败、待复核、已确认、无法判断和需要修正方案等业务状态；具体存储结构由实现确定。
- 处理失败保留原因并允许重试；重启后恢复已保存的进度，不能将中断任务误报为成功。
- 方案变更创建新版本；Prompt 引导 Agent 验证变更并依据对话目标确定重跑范围，通过工具执行。没有固定的版本试跑审批步骤；重跑记录必须包含明确范围，范围外图片不变。
- 新的初步标注与旧人工确认记录分别保留。被重跑图片的新结果必须重新确认；旧确认记录作为历史，不能让新结果自动获得已确认状态。

### 人工复核

- 所有正式结果必须逐张人工确认，不按模型置信度自动通过。
- 六宫格案例展示原图、裁切区域、可编辑题目、可选择的候选图、模型建议与当前答案。
- 单选或多选由方案声明，确认前校验选项和必填字段。
- 支持确认并下一张、上一张、无法判断及快捷键；快捷键应避免干扰文本输入。
- 裁切错误可反馈给 Agent 修正方案。MVP 不加入逐张手动修补裁切区域的工作流。
- 通用矩形标注组件编辑的是标注字段，不代表允许直接修改预处理裁切方案。

### 数据与坐标约定

- 保存原图实际宽高；最终空间标注统一以原图为参考，使用 0～1 范围的归一化坐标。
- 点使用横纵坐标；矩形使用左上角坐标和宽高；有序点保留顺序。
- 选格标注保存稳定选项 ID、各选项在原图中的区域及选中项，题目文字单独保存。
- 裁切区域保留原图位置。裁切图坐标必须映射回原图；涉及缩放等变换时，处理方案必须提供可验证的映射。
- 保存浮点精度，生成实际裁切图片时按统一规则取整。拒绝非有限数、无效尺寸和越界结果，不以静默修正掩盖错误。
- 归一化约定属于本项目数据契约，不承诺兼容其他标注工具的内部格式。

### 导出

- 通用 JSON 是完整结果格式，保留原图标识与尺寸、方案版本、题目、标注字段及确认结果。
- 导出独立数据包，包含原图副本，引用使用包内可解析的位置。
- 六宫格 YOLO 导出将选格框标为 `click` 类别；由内部左上角与宽高转换为归一化中心点与宽高。
- 选格框表示完整格子，不代表格内物体的位置。
- 其他标注类型仅在方案提供明确转换规则时支持对应导出；不能将文字、点或角度强行解释为检测框。
- 同一次 JSON 与 YOLO 导出共享当前已确认图片集合。处于重跑后待复核状态的图片不因存在历史确认记录而进入正式导出。
- 数据包附类别说明，第一版不自动划分训练集和验证集。

## 测试决策

以下两个测试边界沿用用户已确认的选择，并适配 Electron 界面与对话驱动流程。仓库已有仅用于交互验证的 React 原型，但尚无正式 Electron 应用、生产接口或可复用的自动化行为测试；原型的类型检查、构建与浏览器操作记录可作验收场景参考，不代表正式实现已经通过测试。通过公开边界验证行为，避免针对私有函数和组件内部实现编写测试。

### 主要边界：用户通过工作台完成完整标注流程

通过 Electron 窗口中的 React 界面及其公开应用接口，验证对话驱动的导入、Agent 样本验证与批量处理、人工修改、重启恢复、版本重跑及导出。组件与浏览器级验证可用于快速反馈，但不能替代实际桌面应用的启动、preload/IPC、文件选择和进程重启验证。

- 使用自制无品牌的示例图片和可控的 Agent/VLM 测试替身，让网络错误、无效模型响应和重跑结果能够稳定复现。
- 测试替身置于外部模型服务边界，真实执行工作台的数据保存、方案校验、渲染、状态变更和导出逻辑。
- 验证 Agent 能通过工具在无需流程按钮审批的情况下推进处理，且初步标注不能自动进入已确认；重跑不丢失旧人工记录，恢复后成功项不被默认重复处理。
- Prompt 的样本验证指导通过可控 Agent 工具轨迹及真实小样本验收检查；工具接口继续校验数据、任务标识、版本与重复执行，不把建议步骤转成强制审批状态机。
- 使用相同渲染入口展示不同组件组合，覆盖选格以及点、矩形框、有序点的编辑与保存，证明界面由描述驱动。
- 校验未知组件、无效字段绑定、无法判断和处理失败等异常在界面及导出中的行为。
- 验证项目与会话隔离、同一产物标签去重、切换及重启后的布局与草稿恢复，以及跨会话编辑的版本冲突；历史产物引用始终定位到原版本。
- 以原型 A 的已选布局验证左侧导航、主聊天及右侧面板，全屏或收起不改变任务执行状态，后台结果不抢当前焦点。
- 模型替身不能证明真实 Agent 会正确使用工具；另做小规模真实服务验收，确认内置 Agent 能查看图片、写代码、执行测试并提交方案，VLM 能返回被接受的结果。真实服务验收不作为每次运行的确定性回归测试。

### 补充边界：公开标注数据与导出契约

通过公开的标注提交、校验与导出入口验证归一化位置和数据包，避免仅靠截图判断坐标正确性。

- 用人工算出的已知坐标验证原图、裁切图和显示缩放间的位置映射，覆盖非正方形图片及边缘区域。
- 用固定预期值核验 YOLO 转换，避免用与实现相同的计算步骤生成期望值。
- 验证无效坐标被拒绝，选项 ID 与区域对应稳定，导出只包含当前已确认结果。
- 检查 JSON、标签和图像集合一致；复制数据包到其他目录后，其内部引用仍可解析。

### 工程质量约定

- 从首张实现任务建立 ESLint flat config、TypeScript 严格检查、自动化测试及 CI 阻断，统一检查命令对警告也返回失败。
- 自有业务代码初始硬限制：圈复杂度不超过 10；函数有效行数不超过 60（忽略空行和注释）；嵌套深度不超过 3；参数不超过 4。
- React 函数组件同样接受圈复杂度检查。纯展示组件可通过明确的文件范围将函数长度放宽至 100 行；不能对全部 TSX 关闭限制。
- 未修改的第三方组件源码可使用独立、明确的 lint 范围配置；自有业务代码不得放入该范围规避限制。任何例外需具体规则、原因和适用范围。
- 对坐标转换、协议校验、复核状态转换与导出过滤进行行为单元测试；用户流程使用中文“假如／当／那么”验收场景，不为表达格式强制引入独立测试框架。
- 核心领域逻辑初始覆盖率门槛：行与语句不低于 90%，函数不低于 90%，分支不低于 85%；明确统计范围，不以生成代码或第三方组件稀释指标。
- 对坐标、状态转换与导出过滤运行变异测试，初始有效变异得分门槛 80%；分阶段纳入已有模块，报告存活变异并分析原因，不能只追求覆盖率数字。
- 每票验证自身行为；最终 QA 覆盖实际桌面运行、键盘操作、错误反馈、中断恢复和数据包可搬移性。

## 不在范围内

- 模型训练管理、在线验证码推理服务和自动操作第三方网站。
- 多人协作、账号权限体系、远程部署和外部 Agent 接入。
- 混合题型文件夹的自动识别和分流。
- Agent 现场创建并加载任意前端组件。
- 承诺任意题型无需扩展组件即可支持；专用滑块、旋转等交互不属于首版验收。
- 逐张手动修补裁切规则、按置信度自动通过复核。
- 自动划分训练集与验证集、与其他标注工具或 UI 协议的直接兼容。
