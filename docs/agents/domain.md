# 领域文档

本项目采用单一领域文档布局：

- 根目录的 `GLOSSARY.md`：领域术语表，解释项目中的业务概念。
- `docs/adr/`：架构决策记录，解释重要取舍及其原因。

## 探索代码前

阅读 `GLOSSARY.md`（如果存在），以及 `docs/adr/` 中与当前工作有关的决策记录。

这些文件不存在时，直接继续工作。无需提示缺失或预先创建空文件。`/domain-modeling` 会在明确术语或需要记录决策时按需创建它们；`/grill-with-docs` 等流程会调用该 skill。

## 保持术语一致

任务标题、重构建议、问题假设和测试名称中的领域概念，应使用术语表确定的名称。
术语表只解释领域术语，不存放实现细节、需求规格或临时笔记。

如果所需概念尚未收入术语表，先判断是否在引入项目不使用的名称；确有缺口时，交由 `/domain-modeling` 明确。

## 明确决策冲突

如果方案与已有 ADR 冲突，明确指出对应记录和重新讨论的理由，再处理该取舍。
